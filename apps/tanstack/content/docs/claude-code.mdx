Turing Incomplete integrates with [Claude Code](https://claude.ai/claude-code) via MCP (Model Context Protocol). Claude becomes an AI tutor that can see your circuit, push code changes, run simulations, and respond to questions — all in real time.

## What it looks like

You open the app in your browser and Claude Code in your terminal. When you ask Claude to build something, it:

1. Writes the TypeScript circuit definition
2. Pushes it to your browser — the circuit appears on the canvas instantly
3. Runs the simulation and shows you the results
4. Responds to your follow-up questions with full awareness of the circuit state

You can also chat with Claude directly inside the app's chat panel. Your message is forwarded to Claude via a channel notification, and Claude's response appears in the chat — no copy-pasting between terminal and browser.

## Setup

### 1. Install Claude Code

Follow the [Claude Code installation guide](https://docs.anthropic.com/en/docs/claude-code/overview) if you haven't already.

### 2. Add the MCP server

```bash
claude mcp add turing-incomplete npx @turing-incomplete/mcp
```

This registers the Turing Incomplete MCP server with your Claude Code installation. Claude now has access to circuit design tools.

### 3. Open the app

Visit [turing-incomplete.com](https://turing-incomplete.com) or run the app locally. When Claude pushes a circuit, your browser will connect automatically.

## Available tools

Once the MCP server is registered, Claude has access to these tools:

### Building circuits

| Tool | What it does |
|------|-------------|
| `show_circuit` | Push a circuit file to the browser and open a live preview. Watches the file for changes. |
| `get_circuit_state` | Read the current circuit state from the browser — port values, cycle count, inputs/outputs. |
| `simulate_circuit` | Compile and simulate a circuit, returning signal traces. |
| `run_testbench` | Execute a testbench with stimulus, capture waveforms, check assertions. |
| `show_traces` | Push simulation waveforms to the browser for visualization. |
| `show_test_results` | Push test results to the browser. |
| `check_circuit` | Validate circuit structure without running simulation. |
| `get_grammar` | Return the component reference (so Claude can write valid circuits). |
| `get_primitives` | Return the list of available primitives with their ports and parameters. |

## How the connection works

The MCP server runs locally alongside Claude Code. It serves two roles:

1. **MCP tool provider** — Claude calls tools via the standard MCP protocol (stdio transport)
2. **WebSocket bridge** — a WebSocket server on `localhost:19847` connects to the browser

When Claude calls `show_circuit`, the tool pushes the circuit file to the browser over WebSocket. When you type in the app's chat, the message is forwarded to Claude via an MCP channel notification. Claude's response comes back through `push_chat_response`.

```
Claude Code (terminal)
    ↕ MCP (stdio)
MCP Server (local)
    ↕ WebSocket
Browser App
```

### Session management

- **Token auth** — a unique token is generated per MCP server session
- **Auto-reconnect** — the browser retries every 5 seconds if disconnected
- **Cache replay** — if the browser connects after Claude has already pushed a circuit, it receives the cached state immediately
- **Multi-tab** — each browser tab registers as a separate session

## Example workflow

**You:** "Build me a 4-bit counter with a hex display"

**Claude:**
1. Calls `get_primitives` to check available components
2. Writes the circuit: Register + Adder + Constant + HexDisplay
3. Calls `show_circuit` — the circuit appears in your browser
4. Calls `simulate_circuit` to verify it counts correctly
5. Responds: "I've built a 4-bit counter. Click the play button to see it count from 0 to F."

**You:** "Can you add a reset button?"

**Claude:**
1. Calls `get_circuit_state` to see the current circuit
2. Adds a Switch and Mux for reset logic
3. Calls `show_circuit` with the updated circuit
4. The browser updates live — you see the reset switch appear

## Challenges with Claude

The challenge system works especially well with Claude. Open a challenge in the browser, and Claude can:

- Read your current progress (`check_challenge_progress`)
- Give hints without revealing the solution (Socratic feedback)
- Add connections one at a time (`solve_next`) if you're stuck
- Explain why each connection is needed via the chat panel

The challenge chat supports **channel notifications** — when you type in the app's chat, Claude receives your message with full context (which challenge, which level, your current circuit). No need to describe what you're looking at.

## Running without Claude

The app works without Claude Code. You can:

- Write circuit code directly in the editor
- Explore the interactive blog posts
- Embed circuits in your own React app

Claude is an enhancement, not a requirement. The MCP server adds an AI tutor to the experience, but all the tools and content work standalone.
